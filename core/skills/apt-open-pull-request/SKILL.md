# PR 열기

## 순서

1. 메인이 마지막에 한 번 실행한 전체 검증 결과를 쓴다. 그 결과가 없거나 그 뒤에 코드가 바뀌었을 때만 다시 실행한다.
2. 실패한 검증이 있으면 PR을 열지 않고 실패를 고친다. 고칠 수 없으면 PR 대신 막힌 이유를 보고한다.
3. 작업 브랜치를 푸시하고 PR을 만든다. 기본 브랜치에 직접 푸시하지 않는다.
4. Bugbot 또는 저장소의 자동 리뷰가 있으면 요청한다.
5. 병합하지 않는다.

## PR 본문

- 요약
- 수용 조건 체크리스트
- 실행한 검증 명령과 종료 코드
- 가정과 범위 밖
- `docs/harness/runs/`의 실행 기록 경로

베이스 브랜치는 저장소의 기본 브랜치로 한다.
