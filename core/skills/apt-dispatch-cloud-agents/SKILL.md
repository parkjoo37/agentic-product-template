# 작업 위임

로컬 서브에이전트와 Cloud Agent에 같은 브리핑을 쓴다. 서브에이전트는 규칙과 스킬을 물려받지 못하고, Cloud Agent는 이 저장소의 커밋된 파일만 본다.

## 맡기기 전

- 요구사항 문서와 작업 분해 문서가 저장소에 있다. Cloud Agent에 맡기면 커밋되어 원격에 있어야 한다.
- `docs/harness/model-routing.md`의 해당 슬러그가 채워져 있다.
- 열린 위험 결정은 위임하지 않는다.
- 병렬 작업의 수정 허용 경로는 서로 겹치지 않는다.

## 위험도별 경로

- L0: 메인이 직접 답한다.
- L1: `apt-implementer`를 낮은 강도 슬러그로 맡기고, 메인이 diff를 확인한다.
- L2: `apt-implementer` 다음 `apt-verifier`.
- L3: `apt-designer` 설계, 메인 승인, `apt-senior-implementer`, `apt-verifier`.

위임할 때마다 라우팅 표의 모델을 직접 지정한다. L1·L2 검증은 Grok 4.7, L3 검증은 Claude Sonnet 5.5다.

## 브리핑

1. 역할: 설계, 구현, 검증 중 하나. "당신은 이 작업의 메인이 아니다"라는 문장
2. 목표와 완료 조건
3. 수정 허용 경로와 수정 금지 범위
4. 먼저 읽을 스킬과 규칙 경로
5. 관련 `lessons/` 경로. 없으면 없다고 적는다
6. 실행할 관련 테스트. 전체 스위트는 적지 않는다
7. 완료 시 PR을 만들지 말고 브랜치와 검증 결과만 보고한다는 문장

## 부모가 할 일

1. 의존성이 없는 작업만 동시에 실행한다.
2. 실패하면 `apt-retry-cap`을 따른다. 같은 브리핑을 그대로 반복하지 않는다.
3. Cloud Agent를 쓸 수 없으면 같은 경계로 로컬 서브에이전트에 맡기고, 실행 기록에 그 사실을 남긴다.
4. 전부 끝난 뒤 전체 검증을 한 번만 실행한다.
