# 작업 분해

## 결과 파일

요구사항 경로를 읽어 `docs/harness/tasks/<requirement-slug>.md`에 작업을 쓴다.

## 각 작업

- id
- 위험도: `apt-risk-tiers`의 L1, L2, L3
- 결과
- 주로 수정할 경로
- 검증 명령. 그 변경에 대응하는 테스트만
- 완료 조건
- 다른 작업과의 의존성

## 나누는 기준

1. 한 작업은 하나의 수용 조건 묶음만 담당한다.
2. 두 작업이 같은 파일을 수정하면 하나를 합치거나 순서를 의존성으로 적는다.
3. 병렬로 돌릴 작업에는 의존성을 비워 둔다.
4. 위험 결정이 열린 수용 조건은 작업으로 만들지 않는다.
5. 작업이 하나면 분해 문서를 짧게 만들고 구현으로 넘어간다.
